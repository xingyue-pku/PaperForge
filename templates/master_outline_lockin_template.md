# Master Outline Lock-In · 通过反复迭代锁定主大纲

> 用途：在 motivation_lock + genre_landscape_scan + exemplar_learning_dossier 之后、citation_bank 之前，**通过多轮 reviewer 反馈迭代锁定主大纲**（题目 + 节结构 + subsection 论点 + 图表配置 + 句式细节）。
>
> 解决的问题：不锁就开写 = 边写边改结构 = 写完发现核心问题没立住，被审稿人评为"普通综述"或"信息堆积"。
>
> 与上游步骤的关系：motivation 告诉你"为什么"，genre scan 告诉你"什么壳"，exemplar 告诉你"什么风格"——但这些都没告诉你"具体每一节、每一句要立什么论点"。主大纲锁定就是把前 3 个产出**翻译为可写作的结构性产物**。

## 实证背书

- **2026-05 同行评议判断机制综述案例**：稿件从 v7.1（纯反思性述评）经过 5 轮 reviewer 迭代到 v8.7（"过程化转向 + 机制建模" 问题导向述评），结构、命名、句式、图表配置完全改写。**没有迭代环节就只能写出无投稿之家的论文**。
- Alvesson & Sandberg (2020) problematizing review 强调"打开领域空间"，但落地到具体写作仍需结构性锁定才能避免泛化讨论。

## 何时使用（触发条件，任一满足）

1. 上游步骤已完成（motivation_lock + genre_landscape_scan + exemplar_learning_dossier 都已签出）
2. 现有大纲被自己或同侪指出"重点不突出 / 结构散漫 / 普通综述化"
3. 之前 venue 拒稿意见为"贡献不明显 / 论证不聚焦"
4. 跨学科投稿，需要用别的领域读者能接受的结构表达自己的核心问题

## Procedure

### Phase 1 · 草稿大纲 v0

基于上游三件产出，写出初版大纲，含：

- **题目** · 4-element 框架：`主题词 1 + 主题词 2 + 研究领域 + 写作方式`
  - 例：`同行评议判断研究 + 过程化转向 + 学术评价 + 机制建模述评`
- **6-8 节结构**（中文 CSSCI 综述典型为 6 节：引言 + 研究设计 + 三个主体节 + 结论）
- **副标题三段** · 直接 = 全文三大主体节（夏义堃 2025 G-1 pattern）
- **每节 subsection 占位** · 3-5 个子节
- **图表 tentative 清单** · 检索流程 + 核心贡献图 + 辅助证据图 + 数据归类表 + 跨节对照表

### Phase 2 · 多轮 Reviewer 迭代（核心环节）

每轮：

1. **提交当前大纲**给一个"skeptical reviewer"（真人 / 另一 AI agent 扮演审稿人 / PaperForge Reviewer Committee 中的"Desk Reject Editor Simulator"）
2. **Reviewer 提出具体修改建议**（不要泛泛"好/不好"，要点名具体问题）
3. **逐条回应**：
   - Accept → 修改
   - Modify → 反提案 + 解释
   - Reject → 说明为何拒绝（理由要硬）
4. **更新大纲 → 进下一轮**

**停止条件**：连续一轮 reviewer 只能提出表面修改（错字、句式微调），没有结构性、概念性、命名性修改。

### Phase 3 · 锁定检查（10 项 checklist）

宣布"大纲已锁"之前，逐项检查：

- [ ] **题目用 4-element framework**（主题词 1 + 主题词 2 + 研究领域 + 写作方式）
- [ ] **副标题三段直接 = 全文三大主体节**（不是冗余补充）
- [ ] **中心问题一句话明确** — 所有 subsection 都能回扣这一句
- [ ] **每节末有同一收尾句结构**（例如 `"X 推动了 Y，但仍未打开 Z"`）
- [ ] **诊断节与方案节严格区分**（避免 §4 和 §5 重复同一概念）
- [ ] **图表精简**：核心贡献图 ≥ 辅助证据图 ≥ 描述统计图（不要堆知识图谱）
- [ ] **Anchor 文献全部 peer-reviewed**（preprint 不作核心，可作辅助引用）
- [ ] **投稿稿不出现内部代号**（R1/T1/C2 之类的 workflow label 必须删除）
- [ ] **收尾句完成时态**（"本文 + 动词" 不是"本文将" 的开题报告腔）
- [ ] **方法表述与该 venue exemplar 句式一致**（如不是"采用文献综述法"过于平淡，应仿 anchor "以 X 视角对 Y 进行系统综述"）

## 5 项核心写作原则（迭代中反复回扣）

| # | 原则 | 反例 | 正例 |
|---|---|---|---|
| 1 | **少谈"已有研究不足"，多论"哪些视角可以转化"** | "前人研究多属宏观，缺乏微观机制分析" | "已有研究多从政策工具切入，但行动逻辑尚缺乏制度安排层面的深入解释" |
| 2 | **综述 = 问题定位，不是信息堆积** | 罗列"A 说过…B 认为…" | 归纳"围绕核心问题，学界形成了怎样的争论、分歧与对话脉络" |
| 3 | **以概念组 / 争议焦点 / 研究路径整合** | 按时间线 / 作者序 | "围绕 X 议题，学界形成 N 种解释路径：A / B / C" |
| 4 | **勾勒"知识地图"** | 散点列举 | 图谱回答：(1) 有哪些路径 (2) 路径间是互补 / 对立 / 断裂 (3) 本文衔接哪条 |
| 5 | **明确"我的研究要回应什么"** | 综述末尾草草收尾 | "本文在 X 路径基础上，结合 Y 视角，进一步分析 Z 机制" |

## 4-element Title Framework

对照 4 项要素填空：

| 元素 | 内容 | 例（曹树金 2025）| 例（夏义堃 2025）| 例（你的）|
|---|---|---|---|---|
| 主题词 1 | 核心概念 | AI for Science | 系统论 | _____ |
| 主题词 2 | 时代/范畴 | 时代 | 数据信任 | _____ |
| 研究领域 | 具体领域 | 科技情报领域 | 研究述评 | _____ |
| 写作方式 | 文章类型 | 研究范式变革 | 内涵边界、要素结构与实践路径 | _____ |

**好题目**：4 项都填，且副标题三段 = 全文骨架。

**Anti-pattern**：题目里出现"研究进展""综述"会被编辑直接归入普通综述稿——这些词留在副标题或者完全不出现。

## 5 节 vs 7 节 vs 8 节 结构 · 选哪个

- **5 节**（精简型）：引言 + 三主体节 + 结论。适合 8000 字以下 venue（如情报理论与实践）
- **6 节**（最常见）：引言 + 研究设计 + 三主体节 + 结论。适合 10000-15000 字主流 CSSCI 综述
- **7 节**（含独立"既有综述定位"节）：引言 + 既有综述定位 + 研究设计 + 三主体节 + 结论。适合需要明示与既有综述边界的稿件
- **8 节**（最重）：含独立"研究议程"节。论证密度最高但篇幅最大，注意控制

## 每节末"同一收尾句结构"模板

设计你的同一收尾句结构（在每个主体节末尾用，呼应中心问题）：

| 结构模板 | 示例 |
|---|---|
| `路径 X 推动了 Y，但仍未打开 Z` | "路径 A 推动了过程化转向，但仍没有打开判断机制" |
| `问题不在于 X，而在于 Y` | "问题不在于有没有过程数据，而在于过程数据尚未被转化为判断机制模型" |
| `X 是 Y 的必要前提，但不是 Z 的充分答案` | "信号可识别是机制可观测的必要前提，但不是机制建模的充分答案" |

**为什么需要这个结构**：reviewer 阅读时，每节末同一句式重复 = 论证连贯性 = 编辑容易记住稿件结构 = 录用概率上升。

## 三段式过渡总表（§4 → §5 必备）

诊断节（§4 机制缺口）与方案节（§5 建模路径）之间，**必须有一张过渡总表**，三列对照：

| 路径 / 现状 | 缺口 / 诊断 | 方案 / 建模要件 |
|---|---|---|
| 路径 A | A 的缺口 | A 的建模要件 |
| 路径 B | B 的缺口 | B 的建模要件 |
| 路径 C | C 的缺口 | C 的建模要件 |

表的位置：§5 开头（不是 §4 末或 §5 中间）—— 作为 §4 → §5 的过渡 + §5 各 subsection 的总览。

## 输出文件

完成 Lock-In 后产出：

1. **`outline_locked.md`** — 最终锁定大纲（题目 + 6 节结构 + subsection 论点 + 图表清单 + 中心问题句 + 收尾句结构）
2. **`outline_iteration_log.md`** — 每轮 reviewer 反馈 + 决策记录（保留 audit trail，rejected suggestions 也要记录及理由）
3. **更新 `paper_state.json`** · 加入 `outline_lock_date` + `iteration_rounds_count` + `central_question`

## 触发下游 PaperForge 步骤

完成本步骤后才能进：

- Step 4.7 citation_bank（按锁定大纲反推需要的引用类型与密度）
- Step 5 claim_evidence_matrix（按锁定大纲的每个 claim 反推 3 层定位）
- Step 6 实际写作

如果跳过本步骤直接进 Step 4.7 / 5 / 6 —— 大概率写到一半发现结构需要重组，已写章节作废率高。

## 不允许出现的"借口"

- "我大纲想清楚了就直接写吧" → 想清楚 ≠ 锁定。写出来才知道哪里没想清楚
- "反复迭代浪费时间" → 写一稿 8000 字耗时远超过迭代大纲 5 次
- "Reviewer 太挑剔" → 投稿审稿人比你的 reviewer 更挑剔。现在不被挑出来，后面才会被
- "我自己当审稿人就行" → 自己当反 reviewer 几乎做不到——你与作者立场重合，看不到结构盲区。必须找外部 reviewer（同侪 / AI agent）

## 状态变更日志

每轮迭代记录：
- 轮次 / 日期 / reviewer 身份
- 收到的具体修改建议（逐条）
- 接受 / 拒绝 / 反提案 决策 + 理由
- 本轮后大纲版本号
