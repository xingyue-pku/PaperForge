# Venue Index · 候选刊索引（按研究画像圈层组织）

> 用途：`journal_match`（Step 4.56）建候选集时**先读本文件**，从对应圈层里挑候选，而不是每次从零想"还有哪些刊"。索引条目是轻量的（一行一刊）；**全量档案只在某刊真正进入 reach/match/safe 清单时才建**（`venue_profile_template.md`），避免维护一堆用不上的档案。
>
> 圈层依据的研究画像：GenAI × 高校科研 / 风险感知与治理 / 科研信息素养（本索引持有者：北大信息管理系，质性访谈 + 主题分析为主，兼及科学学、研究生教育、认识论权威议题）。画像变了就重划圈层。
>
> 设计来源：`awesome-journal-skills` 的 `venue-index.tsv`（185 刊机读索引）。它按全学科铺，我们按研究画像收——只收本工作流可能真投的刊。它的中文合集不含图情与教育类刊（核心圈为空白，须自建）；少数相邻刊有其内容包，标注在「AJS 参考」列，建档时可先取其材料作底稿再逐项核验。
>
> 维护规则：新刊先进索引再建档；档案建成后把「档案」列改为 ✅ 并链接；收录级别等易变事实**不在索引里断言**，建档时核验。

## 使用规则

1. `journal_match` 跑 Step 2（建候选集）时从本索引对应圈层取候选；索引外的刊要先加进索引（写清匹配点）再参与比较
2. 进入 reach/match/safe 三档清单的刊，若「档案」列为未建档，按 `venue_profile_template.md` 至少建快档（元信息 + 定位栏目 + 审稿决策三节）后才可定档
3. 「AJS 参考」列非空的刊，建档时先拉该包的 `resources/`（官方链接图等）作底稿，**逐项换成自己核验过的来源与日期**，不直接照抄其事实
4. 本索引不承载易变事实（收录级别、录用率、字数、周期），那些进各刊 profile 并标核验日期
